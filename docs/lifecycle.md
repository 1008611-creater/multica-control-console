# 生命周期契约

所有中大型任务都遵循同一条生命周期。阶段不能跳过；如果输入不足，任务进入 `blocked`，而不是用猜测补齐。

| 阶段 | 输入 | 必须产物 | 责任人 | 进入下一阶段条件 |
|---|---|---|---|---|
| DEFINE | 用户目标、问题、项目 ID | Problem Brief / `product-spec` 更新 | 自媒体主控 | 用户、边界、非目标和验收标准明确 |
| PLAN | 已确认规格与约束 | `implementation-plan` 垂直切片 | 自媒体主控 | 每个切片有文件范围、验证方式和风险等级 |
| BUILD | 计划切片、任务模板、真实素材 | 内容/索引/脚本和定向测试 | 内容生产 | 最小产物完成，未越过权限边界 |
| VERIFY | 产物、状态文件、验证命令 | 验证日志与问题清单 | 执行角色 | `npm run verify` 和定向检查通过 |
| REVIEW | 验证结果、变更范围 | Review Report / 待用户拍板项 | 用户或指定 reviewer | blocking 问题为 0，风险有处理方案 |
| SHIP | 已接受产物、发布清单 | 用户执行的发布回执或交付记录 | 用户本人 | 有最终成功回执，或明确保持未发布状态 |
| RETRO | 真实结果、成本、失败记录 | 复盘记录与状态回写 | 数据复盘 | 结论有来源，下一周期动作可验证 |

## 统一失败处理

- 规格不清：回到 `DEFINE`；
- 计划不可验证：回到 `PLAN`；
- 输入、授权或外部服务缺失：进入 `blocked`，记录解除条件；
- 验证失败：保留失败证据，修复后重跑；
- 发布没有最终回执：保持 `awaiting_review` 或 `accepted`，不得写成 `shipped`。
