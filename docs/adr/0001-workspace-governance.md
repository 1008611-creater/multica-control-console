# ADR-0001：采用控制台 + 外部执行现场的治理架构

- 状态：accepted
- 日期：2026-09-21

## 背景

当前仓库包含阶段操作卡、技能副本、项目索引和参考资料，但缺少统一的规格、约束、计划和验收层。Multica 的实际执行发生在外部桌面端和工作目录，原始内容生产资产也位于外部路径。

## 决策

将本仓库定位为可审计控制台，采用四层结构：任务层、规范层、资产层、外部执行现场。根级文件承载跨项目铁律，`docs/` 承载当前产品与架构决策，`projects/` 和 `skills/` 只保存控制台资产与可导入副本。

## 选择理由

- 不搬迁原始资产，降低路径破坏风险。
- 把长期约束与版本验收条件分开，减少规则互相覆盖。
- 统一验证入口，使文档型项目也有可重复的质量门槛。
- 保留人工授权边界，避免把自动化误扩展为自动发布。

## 代价

- 每次跨边界变更都要同步文档和状态。
- 需要维护状态文件和验证脚本。
- 外部 Multica 运行时问题不能仅靠仓库内脚本解决，必须保留运行现场证据。

## 失效条件

若未来仓库演变为实际应用代码库，应新增应用层架构 ADR，并重新评估本控制台分层，而不是把应用逻辑直接塞进现有文档层。
