# ADR 0010：批量抽卡由本地服务持久化调度

- 状态：accepted
- 日期：2026-09-30

## 背景

浏览器页面曾在 `localStorage` 中维护并发槽位和作业轮询。页面刷新、服务重启或提交回执延迟时，无法可靠判断任务是否已经提交，存在重复扣费风险。

## 决策

批量抽卡由 `mj-automation/scripts/batch_queue.py` 负责。每个批次保存为同目录下的 JSON 状态文件，使用同目录临时文件和 `os.replace` 原子更新。服务重启时只读取已持久化的作业号并回读桥接回执；有作业号缺失、状态未知、成品缺失或回执不可信的任务，批次进入暂停并等待人工核查。

并发上限固定为 3。每个工作位分配独立的 `run/batch-slots/<batch>-slot-<n>` 浏览器档案路径，作业提交前持久化工作位和提交意图。平台差异仍由现有桥接适配器处理，通用队列不包含项目专用批次 ID、提示词或输出目录。

前端只调用 `/control/batches` API，不再自行提交、轮询或恢复任务。真实提交、继续批次和人工重新提交都要求用户在本次操作中明确确认可能产生费用；失败和结果待核查不会自动重试。

## 影响

- 批次、任务、回执摘要和成品路径可以在页面刷新及服务重启后恢复。
- 成品文件必须存在且非空，才会进入“已完成”。
- 任务提示词保存在本机批次状态供用户查看；事件和桥接日志不记录完整提示词。
- R7 等既有项目运行目录不被新队列扫描、接管或修改。

## 补充决策：回执关联与文件命名

适配器只有在拿到本次提交产生的可信 `serial` 后才允许下载。仅凭页面图片数量、完成文案或“最新卡片”不能判定成功；缺少 `serial` 时返回 `unassociated_result`，停止抓图并等待人工核查，避免把历史图片当成本次结果。

输出文件名取任务名称，保留中文并清理 Windows 非法字符；文件仍写入任务声明的输出目录。回执记录清理后的输出名，便于页面显示和恢复。




## 补充决策：批次工作位登录与隔离锁

批次登录状态必须由实际任务使用的 `run/batch-slots/<批次>-slot-<序号>` 浏览器档案判断。收到 `need_login` 且桥接回执明确 `submitted=false` 时，任务进入 `login_required`，批次暂停；界面可以启动同一槽位的可见浏览器供用户本人登录。继续操作由后端重新读取该槽位的登录状态，要求用户再次确认本批次可能产生费用，并在提交剩余任务前正常关闭登录窗口释放浏览器锁。状态不明确或登录未验证时保持暂停。

每个工作位使用独立的桥接锁文件，避免三个隔离档案被全局锁意外串行化。登录窗口与生成作业共享该槽位锁，防止同时打开同一个持久化浏览器档案。登录状态文件不保存 Cookie、Token 或提示词。
