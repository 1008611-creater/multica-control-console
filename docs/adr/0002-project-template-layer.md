# ADR-0002：新增可复制模板层

- 状态：accepted
- 日期：2026-09-21

## 背景

ADR-0001 确定了控制台 + 外部执行现场的四层结构。运行一段时间后暴露出一个重复成本：每开一个新项目，都要从零拼装规范文件、文档骨架、验证脚本和忽略规则，而这些内容在 Slice 1-12 中已经被验证过。

参考架构给出的结论同样是：真正值得投入的不是继续堆技能，而是让已经跑通的治理方式可复制。

## 决策

在仓库根目录新增 `templates/`，作为「可复制起点」层，与运行中的控制台内容分离。

- `templates/project-template/` 是独立复制单元，整目录复制到新工作区根目录后即为该新仓库的骨架。
- `templates/README.md` 说明两种路径：整体复制新工作区骨架，或在本仓库内新增项目控制台。
- 模板自带验证脚本、CI 与忽略规则，复制后不依赖本仓库即可自检。

## 选择理由

- 模板是复制单元，不是运行时内容；放在 `templates/` 可避免与 `docs/task-templates/` 的任务输入模板混淆。
- 模板自带验证脚本，使新项目第一天就有质量门槛，而不是等积累问题后再补。
- 模板参与本仓库的敏感信息与 Markdown 结构扫描，可防止骨架本身成为扫描盲区。

## 代价

- 存在两份相似内容（本仓库规范与模板骨架），需要人工同步，存在漂移风险。
- 模板更新需要重新做一次仓库外复制验证，验证成本高于普通文档改动。

## 边界与约束

- 模板内的 `AGENTS.md` 约束的是被复制出去的新工作区，不约束本仓库；本仓库仍以根目录 `AGENTS.md` 为准。
- 模板不是真源。骨架改进必须先在真实使用中验证，再同步回模板。
- 模板不得存放凭据、真实项目数据、媒体产物或运行时日志。

## 失效条件

若未来出现多个模板变体（例如前端项目、内容生产项目各一套），应改为按类型分子目录，并在 `templates/README.md` 给出选择依据，而不是把差异塞进同一个骨架。
