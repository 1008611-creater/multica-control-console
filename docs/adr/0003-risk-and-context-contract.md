# ADR-0003：以风险等级和最小上下文约束任务启动

- 状态：accepted
- 日期：2026-09-26

## 背景

生命周期和任务模板已经存在，但风险等级主要停留在模板文字里，缺少统一的阶段门；“最小上下文”也只在个别任务包中出现，无法阻止智能体扫描无关目录或把历史材料当成当前事实。

## 决策

新增两项横切契约：

1. `docs/risk-levels.md` 统一定义 L0–L3、阶段最低证据和升级规则；
2. `docs/task-templates/context-pack.md` 统一定义任务启动时的必读、可选、禁止读取路径、缺失字段和停止条件。

L1 及以上任务必须能定位一个最小上下文装载包；触及权限、付费、凭据或架构边界的任务不得降级为 L0/L1。

## 选择理由

- 把风险从“备注”变成阶段门，复核时可以判断证据是否足够；
- 把上下文从聊天习惯变成可复制文件，减少历史漂移和无关扫描；
- 不把授权写进上下文包，避免“读到任务”被误解为“获得执行权限”。

## 代价

- 每个 L1 及以上任务都要维护一份上下文包或项目输入包；
- 模板层和运行中控制台各有一份契约，需要同步验证。

## 失效条件

若后续出现多个项目类型或多个执行环境，应按项目类型拆分上下文包模板，并在风险分级文档中明确选择规则，不应继续向单一模板堆例外。
