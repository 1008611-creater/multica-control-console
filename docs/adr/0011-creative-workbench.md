# ADR 0011：以创意、批次和图片组织中文工作台

- 状态：accepted（本地实现；真实平台生成验收未完成）
- 日期：2026-10-07
- 责任人：Codex；单人自审记录见升级验收文档

## 背景

技术诊断、任务编辑和结果混排妨碍创作；同名任务、参数未进入实际请求、刷新后不清楚是否提交，会造成错误和重复劳动。共享浏览器档案的锁也不能支撑三个真实同时运行实例。

## 决策

采用准备创意、运行批次、图片工作区、连接设置四空间，保持原生网页与 Windows WebView2 架构。借鉴 Invoke 的元数据回溯、Comfy 的队列与模板、shadcn 的可组合交互、Fooocus 的预设结构，自行实现；不复制源码或集成它们的生成引擎。

参数校验独立于派发，原始提示词和有效发送文本分别保留；未验平台采用时写 transport_only。请求身份包含提示词、版本、画幅、参数、浏览器档案；启动子进程前原子保存唯一提交意图。未决意图不因超时、force 或服务重启而被重新提交。

共享档案一次只调度一路；独立档案最多三路，各自隔离锁。取消不丢弃已提交回执，恢复只关联原作业。费用授权必须是本次 JSON 布尔 true，不接受字符串、数字或模板继承授权。

图片工作区从真实作业、批次、尝试与回执构建只读索引；收藏、标签、归档另存 annotations。未知字段显示缺，无提示词不提供完整复用。索引拒绝链接和伪图片；结构校验与完整像素解码明确区分。

私有 `/control/` 采用同源 Origin 限制；保留现有 `/v1` 画布契约。新包输出到新目录，运行数据不视为构建缓存，旧安装不自动覆盖或迁移。桌面启动固定 run、batches、batch-slots 到本安装目录，避免继承旧实例环境变量混用数据。

## 影响与验收

新增 workbench_params.py、workbench_assets.py、统一样式和定向验收。队列持久化决策沿用 ADR 0010，本决策补充其共享档案和身份行为。界面、后端和新包均需实际验证；平台登录、生成、费用、高级参数采用与真实并发单列未验。

详细研究来源、生命周期、自审、回滚和证据见 [升级与验收](../workbench-upgrade-2026-10-07.md)。


## 补充决策：人工登录提醒

沿用后端已有 login_required 暂停状态，不新增派发或登录接口。前端仅在任务明确需要登录且回执 submitted=false 时弹窗，跨批次扫描待登录工作位；未知提交仍保留待核查，不因此提示重新提交。

默认开启，用户可在「连接与设置 → 人工登录提醒」关闭；开关及仍待处理的已提醒事件及最近 100 个历史事件保存在当前浏览器，按批次、任务、作业与尝试去重。同一档案的待登录任务合并提醒，已有编辑或费用确认对话框关闭后再提示。人工窗口使用任务专属 /items/{id}/login 接口，保留共享档案和独立槽位的原有隔离。

弹窗只提供打开人工窗口、只读登录检查、查看对应批次及稍后处理。登录核查成功不修改任务状态、不恢复派发、不提交生成；继续生成仍需本次费用确认。工作台保持打开时轮询，后台标签页可能延迟，不提供程序关闭后的桌面通知或强制前台能力。

定向契约、真实设置页面及隔离 UI 证据见升级文档的「人工登录提醒补充」；隔离登录结果不作为真实账号退出、重新登录或生图成功的证明。

## 补充决策：单一权威分发与任务处理入口

目标是按 2026-10-08 用户当次授权收敛 dist，仅保留 Multica-Control-Console-current 目录及同名 ZIP；它们是同一版本的运行与传递形式。current 已构建并通过包内验证，设为权威入口；实际旧分发清理被执行工具策略拒绝，13 个旧项仍在，不得声称目录已收敛。旧目录中发现的单份任务资料已另存并核对哈希，本机生产目录未迁移或删除。带保护检查的手动清理脚本仅通过语法检查，尚未执行。尚未通过验证的候选不能替换权威包。

批次页提供状态与文本组合筛选，保持后端状态与派发顺序不变。已跳过的历史失败留在已跳过分组，待核查、失败和登录异常归需要处理；处理提示不推断扣费、退款或提交成功。没有待派发任务，或仍有未处理异常时，不显示开始/继续入口，原任务重试和付费确认接口不变。

## 补充决策：图库筛选与本地素材交付（2026-10-08）

组合筛选与排序抽为无副作用 gallery-logic.js；选择与比较保持独立，比较上限四张，批量交付上限一百张。复用优先取请求画幅，不能把实际回执对象误当字符串；缺失输入须明确确认，运行状态与付费授权不复用。

原图默认位置与素材位置持久化在 run/library-storage.json，批次已有 outputDir 保持不变。素材交付仅接受图库 ID，从真实作业索引获取源图，拒绝客户端源路径、链接路径、运行数据目录及目标冲突；副本附带来源 JSON，按完整哈希验收。supent 身份及对应目录未确认时，只提供用户可配置的本地素材目录，不宣称已接入其远程接口。

本次用户授权公开发行软件源码与安装包，并升级本机安装；完整本地仓库历史包含浏览器资料，公开发行须使用显式源码清单和独立干净仓库，禁止继续推送该历史。阶段、验证、自审和回滚见 docs/workbench-authority-2026-10-08.md。


## 补充决策：新版工作区为桌面默认入口（2026-10-08）

移除旧原生总览作为启动首页的设计；MainForm 直接承载新版创作工作区，共用既有 WebView2 档案，不创建第二个创作窗口。仅启动和失败时显示连接状态与重试，本机服务诊断置于按需菜单。健康轮询不会重载已就绪页面；服务归属校验、有限恢复与未决任务关闭保护保留。验收必须从 Multica.exe 默认启动开始，不能仅验证 /control 页面或二级入口。发行与验证证据见 docs/workbench-authority-2026-10-08.md 的桌面入口修复记录。


## 补充决策：生成模式必须回读，电影生产按总额度预留（2026-10-08）

用户授权《鲸歌计划》30秒试片最多1000次普通模式v8.2生成。本授权允许该项目内部按质量门槛分轮，不重复请求已给定额度；额度不是消耗目标，也不授权视频、参考图上传或发布。旧适配器选模式失败仅告警，改为在“模式选择”所属选项组回读唯一选中状态；不可确认或模式不符，提交前MODE_NOT_APPLIED停止。回执增加requested_mode、mode_applied与mode_verified，实际底层平台模型仍不凭界面名称推断。模式选择受真实平台验证之前只记录已通过本地合同检查。

额度在本机run/whale30-20261008/authorization.json按批次预留，先持久化再请求执行；重复保留、总额超1000、账本不一致或未知启动回执禁止继续自动提交。首波6项视觉锚点后目视验收，再考虑18项候选。当前自动启动被工具政策拒绝，命令未执行；预留首批6次供用户手动启动，自动巡检只读，不通过定时任务或另一执行方式重试被拒动作。具体镜头、提示词、实际限制和文件位置见projects/whale-pilot/whale30-production-plan-20261008.md。


## 补充决策：桌面故障恢复与状态隔离（2026-10-08，源码未发行）

工作区初始化与导航设置30秒限时。超时或浏览器/渲染进程失败时进入明确失败界面，仅由用户重试重新创建WebView控件，沿用原webview-profile路径；健康页面不因重试连接、服务轮询或辅助GPU进程失败重载。旧控件及非当前NavigationId的回调不得更改新状态。控件初始化等待亦限时，释放时停止定时器。

此恢复只涉及显示页面，不改变批次授权、回执或队列，不重提生成。源码用scripts/test_desktop_recovery.ps1在不初始化浏览器、不导航、不启动服务的状态测试中验证；本机2026.10.08.2的恢复补丁已在本次MJ维修中备份并补装；公开发行未更新，真实故障恢复及视觉仍待验收。最小上下文、复核和限制见docs/film-production-brainstorm-2026-10-08.md。


## 2026-10-08 失败状态与原图关联补充

平台生成结果、图片归属和费用结算是独立证据。平台返回page_reported_failed即记为failed并暂停批次；扣费未知仍保留，不因费用未知把明确失败伪装为继续等待。退款文字不证明实际扣费数值，也不自动允许重提。

适配器等待使用单一截止时间，只有绑定卡片的下载信号证明生成完成。多个新增serial同时出现时不按最新值猜归属；超时或页面消失保留已绑定serial。网络原图只接受outputs路径及文件名精确对应serial的响应；没有可核查来源的Blob和全页图片兜底不进入成品。既有字节、格式和尺寸验证继续执行。

取舍：来源无法核查的旧下载路径可能明确失败，代价是需要核查，不再把其他任务的图报告为本任务成功。测试证据与生效范围见鲸歌计划当前30秒生产方案的“生成链路故障修复与免费回归”章节。未进行真实平台生成或公开发行验收。


## 本地终态与平台排队分开处理

当外层作业status=done而resultStatus=queued/running时，本地runner已退出，不再假装仍有进程可以推进平台任务。批次转result_pending、释放本地槽、保留serial并暂停；不得把它改成pending或自动发起新的生成。真正外层status=running/queued继续等待。重启仅恢复可核查状态，不继承隐含的重新提交许可。

高级参数JSON及对象类型在runner进入浏览器/后台派发之前解析；非法输入明确确认未提交，避免事后解析异常吞掉真实回执。平台失败、费用不明和工具执行拒绝仍是独立问题，不由元数据授权字段或离线测试推断恢复。


## 完整输入与单次点击证据

提交前提示词必须全文回读一致，不能以长度阈值代替内容证据。按钮不可用与点击结果不明分开处理：前者确认未提交，后者保持未知，任何点击异常都不得在同一调用中换按钮再次尝试。此规则不新增人工确认，也不撤销已有用户授权；其目的是防止错词出图和同一尝试重复提交。


浏览器点击回执与平台受理证据分离：点击成功后维持submitting且提交未知；观察并唯一关联到新增serial后才记录submitted=true及platform_generating。无serial超时不推断已受理或未扣费，不允许自动重新提交。


## 浏览器状态时效与协作退出（2026-10-08）

真实接口曾将2026-10-03的control-browser状态报告为当前已登录；保存的PID 26348已属于Autodesk GenuineService。PID存活不能证明旧登录观察仍有效。共享与槽位状态现在同时要求PID存活和最近30秒的心跳；starting阶段允许120秒，缺失、无时区、未来或过期时间均不作为当前运行证据。过期或意外退出会同时清除loggedIn和loginState，避免共享恢复入口继续信任旧登录。只有刚由控制器明确stopped_by_console释放档案锁的状态，可以短时保留已核验loginState。

停止可见浏览器改为写入该控制器专属stop文件，由browser_control.js处理退出及档案锁释放；不再根据持久PID调用taskkill或os.kill。若控制器无响应，不强杀、不终止其他程序，也不以旧状态自动提交。此决定不修改浏览器档案或授予登录、生成权限。8项隔离回归验证过期且PID存活、异常时间、新鲜状态、控制器退出、共享锁释放、槽位以及协作停止。真实接口重载后旧登录变为unknown；没有调用真实浏览器停止或平台生成。


## 弹窗清理边界与审查后恢复（2026-10-09）

真实首次恢复触发旧清理器多次重复报告68个关闭操作。弹窗清理改为仅作用于可见对话框及明确活动窗口，精确关闭动作，不点击全页模糊文本或遮罩角落，不使用force。登录、验证码和付款等窗口保留给用户；每个容器最多单击，关闭效果可核验才计数，并限制总耗时与容器数。原未知提交禁止重试规则保持。

旧工具拒绝是历史事实，不能靠编辑标记自称解除。权限环境实际改变后，允许经正式require_escalated审查执行具体恢复动作，保留旧证据和额度预留；明确未执行的既有预留可复用，不重复预留。未知启动回执仍先记不明并停止，不自动重复POST。此次只获准恢复首批6项，后续额度仍以用户原授权及实际核查门槛为准。
