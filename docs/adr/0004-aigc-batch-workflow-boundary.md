# ADR-0004：AIGC 批次由 Multica 编排、由本地桥执行

- 状态：accepted
- 日期：2026-09-26

## 背景

AIGC 抽卡同时包含两类动作：一类是批次配置、授权、顺序、选图和回执管理；另一类是实际调用平台、等待出图和下载文件。把两类动作混在一个聊天任务里，会导致历史授权被误用、失败后重复扣费、候选图被误写成最终结果。

## 决策

采用“一个批次一个 Multica 任务”的边界：

- **Multica** 保存批次配置、状态机、授权门、受控并发进度、用户选图和回执；
- **本地抽卡桥** 只负责实际提交、等待、序列号补下载和文件校验；
- **平台 App** 仍由用户本人登录、确认和发布；
- 生成、选图和发布使用三道独立的人工作业门。

批次状态固定使用：

```text
draft → linted → awaiting_authorization → running_bounded_parallel → awaiting_selection → accepted
```

执行异常进入 `blocked`，解除后回到最近一个仍然满足门槛的状态。

## 选择理由

- 批次状态和授权留在一个可审计位置，便于复盘；
- 抽卡桥可以替换，不会把平台细节写进 Multica 的核心规则；
- 免费检查可以单独运行，不会误触付费接口；
- 失败时保留原始作业号和序列号；可免费补下载的先补下载，确认生成失败后可在本批授权内、最多三个并发槽位中重提交，不因单张失败停整批；
- 每次重提都必须记录 `retry_of`、新作业号、序列号和扣费状态；用户选图和发布授权不会被“已经出图”隐式替代。

## 代价

- 每个批次都需要维护一份配置和回执；
- Multica 与桥之间需要保持字段契约一致；
- 目前仍需要用户本人完成平台登录、选图和发布。

## 失效条件

如果未来出现多个平台、多个执行桥或批次状态扩展，必须先更新状态契约和回执格式，再修改具体桥；不能在单个 Issue 里增加临时状态名。
