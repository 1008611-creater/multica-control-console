# Multica 中文抽卡生产工作台：产品愿景与首版规格

更新时间：2026-09-27
状态：用户已明确产品方向；本文描述目标体验，不代表功能已实现

## 1. 一句话定位

Multica 是一款本机运行的中文抽卡生产工作台：把提示词、参考资产、参数、并发队列、真实回执和成品文件放在同一条可核对的生产链路里。

它的目标不是替用户猜平台结果，而是让用户清楚知道：准备了什么、提交了什么、平台实际返回了什么、成品落在哪里、失败后能否安全重提。

## 2. 理想用户体验

用户打开软件后，先看到项目总览，而不是一堆技术日志。整个流程只有五个主要动作：

1. 导入或新建一批任务。
2. 检查提示词、参考图、比例、版本、标签和重复项。
3. 明确确认本批任务后，按三并发进入队列。
4. 在队列中看到每一项的真实状态、回执、扣费确定性和成品位置。
5. 导出本批记录，交给后续剪辑、归档或复核。

任何时候都能回答四个问题：

- 现在正在做哪几张？
- 还有哪些等待？
- 哪些已经有真实成品？
- 哪些失败可以重提，重提会不会再次扣费？

## 3. 产品原则

### 3.1 结果优先

“已完成”只代表有可回读的真实成品、回执或明确的失败证据。计划、按钮点击、进程启动和页面显示都不能单独算完成。

### 3.2 中文优先

面向普通用户的文字全部使用简体中文。英文只保留在必要的外部平台名称、文件扩展名和可复制的原始回执中，并提供中文解释。

### 3.3 可控自动化

启动软件不会自动登录、自动提交、自动重试、自动发布或自动付费。用户可以打开浏览器控制，但每个会产生外部影响的动作都要有清楚的确认点。

### 3.4 三并发是队列规则

“保持三并发”指最多同时运行三个可执行任务。某一项结束、失败或进入等待时，队列才补充下一项。页面必须显示当前并发数、空闲槽位和补位原因。

### 3.5 证据和推断分开

状态来源分为真实桥回执、真实平台页面、已保存文件、用户确认和系统推断。推断不能伪装成平台事实；费用未知统一显示“缺”。

### 3.6 可恢复

软件升级、关闭浏览器或重启桥服务，不得删除任务、回执、输出文件、浏览器档案和本地配置。所有任务都能从上次已保存的状态继续查看。

## 4. 信息架构

### 4.1 总览

总览只展示当前真正需要关注的事情：

- 本批任务进度：已完成、进行中、等待中、失败、需登录、需人工确认。
- 并发状态：运行中 0/3、1/3、2/3 或 3/3。
- 最近回执：最后一次平台响应时间、结果类型、成品数量。
- 待处理事项：需要登录、需要确认扣费、下载失败、可安全重提。
- 运行环境：桥服务、浏览器控制、自动看护是否开启。

总览不展示无关的进程编号、调试堆栈和内部路径；需要时可在“详情”展开。

### 4.2 任务队列

队列是软件的核心页面，采用表格加详情抽屉：

| 字段 | 说明 |
|---|---|
| 编号 | 本批内稳定编号，如 C09 |
| 名称 | 用户给任务的短名称 |
| 类型 | 首帧图、人物图、场景图、道具图等 |
| 状态 | 使用统一中文状态模型 |
| 队列位置 | 等待序号或“运行中” |
| 尝试次数 | 初次提交、第一次重提等 |
| 并发槽位 | 1、2、3 或空 |
| 费用 | 已知数字、0、或“缺” |
| 成品 | 文件数量和可打开位置 |
| 操作 | 查看、暂停、重提、标记、导出 |

队列顶部固定显示“当前三并发”和“本批授权范围”，避免用户误以为系统会无限提交。

### 4.3 任务详情

详情页按时间顺序展示一条任务的完整证据链：

1. 原始输入：提示词、负面提示词、比例、版本、参考资产和标签。
2. 提交记录：提交时间、提交方式、平台任务标识和原始回执。
3. 状态变化：排队、运行、成功、失败、需登录、下载失败等。
4. 扣费信息：已确认扣费、已确认未扣费、未知（显示“缺”）。
5. 成品索引：文件名、尺寸、哈希、保存位置和预览入口。
6. 重提判断：为什么允许或禁止重提，以及下一次动作会不会产生新费用。

### 4.4 成品与资产

按项目、批次和资产类型浏览：人物、场景、关键道具、首帧图、其他参考图。每个文件显示来源任务、生成尝试、时间、尺寸和哈希。

这里的“预览”只读取已有文件。软件不通过本地修图、拼图或截图加工来制造权威生产图。

### 4.5 历史与对账

支持按批次导出 JSON、CSV 和可读报告，至少包含任务编号、原始提示词摘要、所有尝试及其平台回执、最终状态、成品文件清单、费用字段和证据来源、未验证项目及人工决定记录。

### 4.6 设置与自检

设置页只放本机工作台配置：保存目录、并发上限、桥地址、浏览器控制开关、日志级别和数据保留策略。

“免费自检”必须明确写出不会登录、不会提交、不会出图、不会扣费。自检结果用中文说明，并提供可复制的诊断摘要。

## 5. 统一状态模型

界面只使用以下中文状态，内部英文值可保留在接口中：

| 中文状态 | 含义 | 是否占用并发 |
|---|---|---:|
| 待检查 | 输入还没有通过本地检查 | 否 |
| 待确认 | 等待用户确认本批提交范围 | 否 |
| 排队中 | 已进入队列，等待空闲槽位 | 否 |
| 提交中 | 正在向桥或平台提交 | 是 |
| 平台处理中 | 平台已接收，等待结果 | 是 |
| 成品回收中 | 已有结果，正在保存文件 | 是 |
| 已完成 | 成品和回执均可核对 | 否 |
| 失败待判断 | 有失败证据，但扣费或可重提条件未明确 | 否 |
| 可安全重提 | 已确认失败且未扣费，允许再次提交 | 否 |
| 禁止重提 | 已扣费、状态不明或重复提交风险高 | 否 |
| 需登录 | 需要用户在可见浏览器中完成登录 | 否 |
| 下载失败 | 平台结果存在，但本地文件尚未完整保存 | 否 |
| 已暂停 | 用户主动暂停，保留当前证据 | 否 |

只有“提交中”“平台处理中”“成品回收中”计入三并发。失败不会自动停止整批；它进入判断区，只有明确标记为“可安全重提”后才允许再次入队。

## 6. 三并发与重提规则

### 6.1 并发调度

- 上限固定为 3，可在设置中改小，但默认不超过 3。
- 每个槽位只能绑定一个任务尝试。
- 任务结束后才释放槽位；失败判断期间不占用槽位。
- 队列按用户指定顺序执行，除非用户明确调整优先级。
- 服务重启后从已保存状态恢复，不重复提交已进入平台的尝试。

### 6.2 失败处理

失败后软件必须先读取平台结果、桥回执和扣费确定性：

- 明确未扣费：标记“可安全重提”，等待用户点击重提。
- 明确已扣费：标记“禁止重提”，保留回执并提示人工处理。
- 无法确认：标记“失败待判断”，不能自动重提。
- 只有下载失败：保留平台任务标识，优先执行补下载，不新建平台任务。

用户可以把某一项重新放回队列，但每次重提都必须产生新的尝试记录，不能覆盖历史记录。

## 7. 视觉和交互标准

### 7.1 视觉方向

采用“专业生产工具”而不是“炫技后台”的感觉：浅色主界面、深色文字、明确的状态色、稳定的卡片和表格、少量动效。重点是信息层级和可读性。

建议颜色语义：绿色表示已完成，蓝色表示进行中，黄色表示需要确认或等待，红色表示失败或禁止重提，灰色表示暂停或历史。颜色不能是唯一提示，必须同时显示中文文字和图标。

### 7.2 交互细节

- 任何会产生费用或外部提交的按钮，都显示动作对象和影响范围，例如“提交本批 12 项”。
- 离线、桥未启动或登录状态不明时，付费提交按钮禁用，并说明原因。
- 空列表要说明下一步怎么导入任务，不能只显示“暂无数据”。
- 加载中、连接失败和数据为空使用不同提示。
- 用户点击危险动作后，二次确认框必须说明任务编号、尝试次数和费用确定性。
- 页面刷新不会丢失筛选条件和当前选中任务。

## 8. 首版范围

### MVP 必须有

- 全中文总览、队列、详情、成品、历史、设置页面；
- 三并发状态展示和队列补位；
- 本地提示词和参数检查；
- 手动提交确认；
- 真实回执读取；
- 失败判断和手动安全重提；
- 成品文件索引与打开入口；
- JSON/CSV 导出；
- 服务、浏览器、看护状态控制；
- 升级保留本地数据；
- 免费自检。

### 第二阶段

- 批量导入 CSV/JSON 模板；
- 任务模板和资产引用库；
- 批次对比、重复提示词检测和版本差异；
- 更细的权限确认和操作审计；
- 打包后的跨机器诊断工具。

### 暂缓

- 自动登录；
- 自动发布；
- 自动支付或充值；
- 未经确认的无限重试；
- 本地修图冒充生产结果；
- 复杂团队协作和云端账号体系。

## 9. 验收标准

产品进入下一轮开发前，至少要能用一个离线样例批次演示完整链路：导入 6 项任务、显示三并发、完成状态变化、模拟一项可安全重提和一项禁止重提、生成真实格式的本地回执报告，并且不会调用平台或付费接口。

接入真实桥后，必须另外核对页面状态是否来自真实接口、失败扣费和下载失败是否能正确区分、重启后是否不会重复提交、三并发是否真实生效、生成文件是否能按任务准确回溯、登录和付费动作是否仍由用户明确触发。

## 10. 后续开发顺序

1. 修正状态文件的可读编码，并把本规格登记为当前产品基线。
2. 按本规格重做页面信息架构和中文文案。
3. 先接入离线样例队列，完成三并发和状态机演示。
4. 再接入真实桥的只读状态和回执。
5. 最后在用户当次明确授权下，验证一次真实提交链路。

本文件是产品定义，不代表真实平台已经登录、已经提交或已经生成任何成品。
