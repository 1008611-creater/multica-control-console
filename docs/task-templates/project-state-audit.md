# 模板：项目状态一致性审计

## 元数据

- 风险等级：L1
- 责任角色：自媒体主控
- 外部动作：无登录、无发布、无付费生成

## 目标

确认一个项目的身份、状态、交付物、阻塞项和授权边界与控制台索引一致。

## 输入

- `PROJECT_CONTEXT.md`
- `CONSTRAINTS.md`
- 项目 `project_state.yaml`
- 项目 `README.md`
- `projects/README.md`

## 输出

- 一份审计回执，包含逐项 PASS/FAIL 证据；
- 不一致项、影响范围和修复建议；
- 明确下一步及其授权门。
- 推荐命令：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/audit_project.ps1 -ProjectDir <项目目录>`
- 兼容入口：同一脚本也接受 `-ProjectRoot <项目目录>`，并额外报告阶段、冠军、缺失交接文件和最早缺口。
- 最早缺口按上游优先：先报告缺失交接文件，再报告阶段/冠军缺失；这些字段齐备后，才报告待用户验收的资产。
- `AUDIT PASS` 仅表示控制台契约检查通过；若项目上下文或输入包缺失，必须同时报告生产审计阻塞，不得视为生产就绪。

## 硬约束

- 只读审计，不修改项目业务资产和状态文件；
- 不登录平台、不发布内容、不触发付费生成；
- 缺失字段写「缺」，不用默认值或推测补齐；
- 审计结论必须附文件路径或命令证据。

## 验收

- [ ] `project_id` 在状态文件、项目 README 和项目索引中一致；
- [ ] 状态属于契约枚举；
- [ ] 交付物路径可定位，缺失项明确写出；
- [ ] `blockers` 与项目内部待审核项没有被混为一谈；
- [ ] 授权边界完整，未触发外部动作；
- [ ] 回执保存到项目 `receipts/` 目录。

## 失败处理

发现身份、状态或授权不一致时，输出差异清单和影响范围，不擅自改状态；无法确认的字段写「缺」并列为待用户拍板项。
