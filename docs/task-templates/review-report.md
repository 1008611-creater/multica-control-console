# 模板：复核报告（REVIEW）

## 元数据

- 风险等级：L2
- 责任角色：自媒体主控
- 把关角色：用户本人
- 项目身份：填写不可变 `project_id`

## 目标

在交付或发布前，以独立视角复核产物是否满足验收标准，把 blocking 问题收敛到 0，并留下可复核的证据。

## 输入

- 已验证产物及其文件路径；
- `docs/acceptance.md` 中的对应条款；
- 验证命令输出（`npm run verify` 与定向检查）；
- 本次变更范围说明。

## 输出

一份复核报告，按优先级分组：

- `[blocking]`：不修复不能交付；
- `[important]`：影响质量或可维护性；
- `[nit]`：可选改进；
- `[praise]`：值得保留的做法。

每条包含：文件与位置、问题、为什么重要、建议的验证或修复方式。

## 硬约束

- 只复核，不修改业务产物，不代替用户做审美或发布决定；
- 结论必须附证据（文件路径或命令输出）；
- 不登录、不发布、不触发付费生成；
- 无法验证的项标记为「缺」，不得写成通过。

## 验收

- [ ] 逐条对照 `docs/acceptance.md` 给出 PASS/FAIL；
- [ ] blocking 问题为 0，或已明确列出阻断项与影响范围；
- [ ] 风险有处理方案，待用户拍板项单独列出；
- [ ] 报告结论与验证命令输出一致。

## 失败处理

存在 blocking 问题或证据不足时，状态保持 `awaiting_review`，不得进入 SHIP；把未通过项写回问题清单并给出复验条件。
