# 模板：最小上下文装载包

## 元数据

- 风险等级：L1；跨模块、状态模型、权限或付费动作时升级为 L2/L3
- 生命周期阶段：横切 DEFINE → RETRO
- 责任角色：项目负责人或当前执行角色
- 把关角色：用户本人或指定复核人
- 项目身份：填写不可变 `project_id`

## 目标

把一次任务真正需要读取的事实收敛成一份有顺序的清单，避免智能体扫描无关目录、把历史材料当成当前状态，或在缺失输入时自行猜测。

## 输入

- `PROJECT_CONTEXT.md` 与 `CONSTRAINTS.md`；
- `docs/risk-levels.md`、`docs/lifecycle.md`；
- 对应项目的 `project_state.yaml`、项目 README 和必要回执；
- 当前任务模板、用户原话和已授权范围。

## 输出

一份最小上下文清单，至少包含：

1. 必读文件及读取顺序；
2. 可选文件及使用条件；
3. 明确禁止读取或修改的目录；
4. 已确认事实、缺失字段和停止条件；
5. 产物路径、验证命令和回写位置。

## 最小上下文

按以下顺序装载，读到足以判断任务是否可执行即可停止：

1. 项目身份：`project_id`、`project_state.yaml`、项目 README；
2. 规则边界：`AGENTS.md`、`CONSTRAINTS.md`、对应风险等级；
3. 任务输入：用户原话、所选任务模板、相关真实素材路径；
4. 验收证据：`docs/acceptance.md`、定向验证命令和既有回执；
5. 只有任务明确需要时，才读取外部只读引用或历史归档。

## 硬约束

- 必读文件缺失、项目 ID 不一致、授权范围不清或当前阶段缺失时，任务进入 `blocked`；
- 未知字段写「缺」，不使用默认值、历史值或目录名推断当前状态；
- 不扫描无关目录，不读取凭据，不把外部运行时日志当作唯一事实来源；
- 上下文包只描述输入和证据，不授予登录、发布或付费生成权限。

## 验收

- [ ] 项目 ID 在上下文包、状态真源和任务正文中一致；
- [ ] 必读、可选、禁止读取三类路径分开列出；
- [ ] 每个关键事实都有来源或明确标记为「缺」；
- [ ] 写出停止条件、产物路径和验证命令；
- [ ] L1 及以上任务能在一个上下文包内启动，不需要扫描整个仓库。

## 失败处理

上下文不足或来源冲突时，停止执行并输出“缺失项 + 冲突项 + 解除条件”；不要通过扩大扫描范围或猜测默认值继续推进。
