# 风险分级与阶段门

风险等级决定一项任务需要多深的验证、复核和授权。生命周期决定先后顺序；风险等级决定每个阶段的最低证据深度。两者同时生效，不能用低风险名义跳过阶段。

## 等级定义

| 等级 | 典型范围 | 最低证据与动作 |
|---|---|---|
| L0 | 文案、模板、纯索引，不改变状态模型或权限边界 | `npm run verify`；一次结构复核 |
| L1 | 单个技能、单个项目控制台、只读审计 | 定向检查；一次独立复核；留下文件或命令证据 |
| L2 | 跨模块、状态模型、任务接口、外部执行编排 | 契约检查；文档同步；回归验证；Review Report |
| L3 | 凭据、权限、付费生成、数据、部署或架构边界 | 当次授权；安全审计；回滚方案；运行验证；审计回执；用户复核 |

## 阶段挂钩

| 阶段 | 所有等级都必须有 | L1 及以上 | L2 及以上 | L3 额外要求 |
|---|---|---|---|---|
| DEFINE | 问题简报、项目 ID、非目标 | 独立列出缺失输入 | 写明跨模块影响 | 写明授权主体与禁止动作 |
| PLAN | 垂直切片与退出条件 | 文件范围和定向验证 | 依赖、回滚和风险记录 | 安全审计和人工停点 |
| BUILD | 真实产物或明确阻塞 | 定向产物检查 | 跨模块回归 | 不执行未授权外部动作 |
| VERIFY | `npm run verify` 或等价验证证据 | 定向检查 | 契约与回归检查 | 运行证据与安全结果 |
| REVIEW | 复核报告 | blocking 问题清单 | 变更范围与风险处置 | 用户拍板与授权证据 |
| SHIP | 发布清单或明确未发布 | 仅内部交付可保留草稿 | 交付回执 | 用户最终回执；无回执不得写 `shipped` |
| RETRO | 真实结果或明确缺失 | 失败与下一步 | 成本、状态和影响 | 安全事件或权限变更审计 |

## 升级规则

- 任务同时符合多个等级时取最高等级。
- 触及登录、发布、付费生成、凭据、外部数据、状态模型或架构边界时，至少升级为 L2；触及权限或付费动作时升级为 L3。
- 风险等级不确定时写「缺」并进入 `blocked`，不得按 L0 处理。
- `## 元数据` 必须记录风险等级；L1 及以上任务还必须能定位对应的最小上下文装载包。

## 证据命名

- 问题定义：`docs/task-templates/problem-brief.md`
- 最小上下文：`docs/task-templates/context-pack.md` 或项目控制台的输入包
- 复核结论：`docs/task-templates/review-report.md`
- L2/L3 架构或边界变化：`docs/adr/` 下的 ADR 与项目 `receipts/` 回执
