# 产品规格：Multica 工作区控制台

## 1. 用户与问题

用户是需要用 Multica 编排自媒体内容生产、漫剧制作和数据复盘的项目负责人。当前问题不是缺少素材，而是流程、状态、约束和验收分散在多份操作卡里，导致任务启动依赖记忆，变更难以复核。

## 2. 目标

在不改变现有生产资产和人工发布红线的前提下，提供一个可审计的工作区：任何任务都能找到上下文、明确输入输出、按风险分级验证，并把真实结果沉淀回项目状态。

## 3. 最小可交付范围

- 一份项目上下文：`PROJECT_CONTEXT.md`
- 一份长期约束：`CONSTRAINTS.md`
- 一套产品/架构/计划/验收文档：`docs/`
- 一个统一验证入口：`npm run verify`
- 一个权威项目状态样例：`projects/天宫漫剧/project_state.yaml`

## 4. 核心用户流程

```text
目标/问题
  → 规格与约束
  → 垂直切片计划
  → Multica 任务/智能体执行
  → 产物与真实证据
  → 验收与复核
  → 状态更新/复盘
```

## 5. 验收标准

1. 新任务能在 5 分钟内找到项目上下文、相关规范和验收条件。
2. 任何任务都能明确区分草稿、待审核、已发布和已复盘。
3. `npm run verify` 在干净工作区执行成功，并能发现缺失规范或敏感信息模式。
4. 生产资产仍通过现有路径引用，原始目录不被复制或改写。
5. 发布、登录和付费生成仍需用户当次授权。

## 6. 明确不做

- 不构建新的发布机器人。
- 不以自动化脚本替代人工平台确认。
- 不虚构业务数据或成功率。
- 不把所有技能一次性塞进所有智能体。
