# ADR 0001 · 仓库只做规范、验证与索引

## 背景

项目需要同时容纳规范、脚本、资产索引和外部系统的交付结果。如果把这些内容混在一起，规范会被实现细节淹没，外部凭据也容易流入仓库。

## 决策

本仓库采用四层边界：任务入口层、规范层、资产层、外部执行现场。

仓库负责：目标与边界、可验证的验收条件、自动检查、资产索引与结果沉淀。

仓库不负责：登录、发布、付费调用，以及原始生产目录的搬迁或改写。

## 影响

- 好处：规范与实现解耦；外部系统可替换；凭据有明确的不入库规则。
- 代价：跨边界动作需要人工授权并留下证据，无法完全自动闭环。
- 约束：新增目录或跨层依赖必须先更新 `docs/architecture.md` 并追加 ADR。

## 状态

已采纳。后续如需改变边界，追加新的 ADR，不修改本文件结论。
