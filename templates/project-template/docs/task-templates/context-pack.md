# 模板：最小上下文装载包

## 元数据

- 风险等级：L1；跨模块、状态模型、权限或付费动作时升级为 L2/L3
- 生命周期阶段：横切 DEFINE → RETRO
- 责任角色：项目负责人或当前执行角色
- 把关角色：用户本人或指定复核人
- 项目身份：填写不可变 `project_id`

## 目标

把一次任务真正需要读取的事实收敛成一份有顺序的清单，避免扫描无关目录或把历史材料当成当前状态。

## 输入

- `PROJECT_CONTEXT.md` 与 `CONSTRAINTS.md`；
- `docs/risk-levels.md`、`docs/lifecycle.md`；
- 对应项目的状态真源、项目 README 和必要回执；
- 当前任务模板、用户原话和已授权范围。

## 输出

- 必读文件及顺序；
- 可选文件及使用条件；
- 禁止读取或修改的目录；
- 已确认事实、缺失字段和停止条件；
- 产物路径、验证命令和回写位置。

## 最小上下文

1. 项目身份与状态真源；
2. 根级规则与风险等级；
3. 当前任务模板与用户输入；
4. 验收条件与既有回执；
5. 仅按任务需要追加历史或外部只读引用。

## 硬约束

- 必读文件缺失、项目 ID 不一致或授权范围不清时进入 `blocked`；
- 未知字段写「缺」，不使用默认值或历史值推断；
- 不扫描无关目录，不读取凭据，不把上下文包当作授权证明。

## 验收

- [ ] 项目 ID 与状态真源一致；
- [ ] 必读、可选、禁止读取三类路径分开列出；
- [ ] 关键事实都有来源或标记为「缺」；
- [ ] 写出停止条件、产物路径和验证命令。

## 失败处理

上下文不足或来源冲突时，停止并输出缺失项、冲突项和解除条件；不要通过扩大扫描范围或猜测默认值继续推进。
