# 风险分级与阶段门

风险等级决定一项任务需要多深的验证、复核和授权。生命周期决定先后顺序；风险等级决定每个阶段的最低证据深度。

## 等级定义

| 等级 | 典型范围 | 最低证据与动作 |
|---|---|---|
| L0 | 文案、模板、纯索引 | `npm run verify`；一次结构复核 |
| L1 | 单个模块或只读审计 | 定向检查；一次独立复核 |
| L2 | 跨模块、状态模型、任务接口 | 契约检查；文档同步；回归验证；复核报告 |
| L3 | 凭据、权限、数据、部署或架构边界 | 当次授权；安全审计；回滚方案；运行验证；审计记录 |

## 阶段挂钩

| 阶段 | 必须产物 | L1 及以上 | L2 及以上 |
|---|---|---|---|
| DEFINE | 问题简报 | 缺失输入清单 | 跨模块影响与授权主体 |
| PLAN | 垂直切片 | 文件范围与定向验证 | 依赖与回滚 |
| BUILD | 真实产物 | 定向检查 | 跨模块回归 |
| VERIFY | 验证证据 | 定向检查 | 契约与回归 |
| REVIEW | 复核报告 | blocking 清单 | 风险处置与用户拍板 |
| SHIP | 发布清单或未发布记录 | 草稿边界 | 交付回执 |
| RETRO | 事实复盘 | 失败与下一步 | 成本与影响 |

## 升级规则

- 同时符合多个等级时取最高等级。
- 触及权限、付费动作、状态模型或架构边界时不得降级。
- 风险不确定时写「缺」并进入 `blocked`。
- L1 及以上任务必须定位 `docs/task-templates/context-pack.md` 或项目输入包。
