# 生命周期契约

所有中大型变更都走同一条生命周期。阶段不能跳过；输入不足时任务进入阻塞并记录解除条件，而不是用猜测补齐。

| 阶段 | 输入 | 必须产物 | 责任人 | 进入下一阶段条件 |
|---|---|---|---|---|
| DEFINE | 用户目标、问题、项目身份 | 问题简报 / `product-spec` 更新 | 项目负责人 | 用户、边界、非目标和验收标准明确 |
| PLAN | 已确认规格与约束 | `implementation-plan` 垂直切片 | 项目负责人 | 每个切片有文件范围、验证方式和风险等级 |
| BUILD | 计划切片、任务模板、真实素材 | 实现产物和定向测试 | 执行角色 | 最小产物完成，未越过权限边界 |
| VERIFY | 产物、状态文件、验证命令 | 验证日志与问题清单 | 执行角色 | `npm run verify` 和定向检查通过 |
| REVIEW | 验证结果、变更范围 | 复核报告与待用户拍板项 | 用户或指定复核人 | 阻塞问题为 0，风险有处理方案 |
| SHIP | 已接受产物、发布清单 | 用户执行的发布回执或交付记录 | 用户本人 | 有最终成功回执，或明确保持未发布状态 |
| RETRO | 真实结果、成本、失败记录 | 复盘记录与状态回写 | 复盘角色 | 结论有来源，下一周期动作可验证 |

## 阶段入口

- DEFINE 的固定产物是问题简报：`docs/task-templates/problem-brief.md`。
- REVIEW 的固定产物是复核报告：`docs/task-templates/review-report.md`。
- SHIP 阶段以 `release-checklist.md` 为唯一入口。
- RETRO 阶段以 `retro-template.md` 为固定产物。
- 每个阶段的产物都必须落到仓库内的真实文件，不能只存在于对话里。
- 风险分级与阶段最低证据见 `docs/risk-levels.md`；L1 及以上任务还必须先形成最小上下文装载包。

## 最小上下文装载

任务启动时按 `docs/task-templates/context-pack.md` 装载项目 ID、状态真源、根级约束、任务模板和验收条件。历史回执、外部只读目录和无关技能只能按任务需要追加读取；必读项缺失时进入 `blocked`。

## 统一失败处理

- 规格不清：回到 DEFINE。
- 计划不可验证：回到 PLAN。
- 输入、授权或外部服务缺失：进入阻塞，记录解除条件。
- 验证失败：保留失败证据，修复后重跑。
- 对外交付没有最终回执：状态保持等待确认，不得写成已完成。

## 与风险等级的关系

生命周期规定阶段顺序，`CONSTRAINTS.md` 的风险分级规定每个阶段要做多深。二者同时生效：低风险改动可以只做结构检查，但不可以跳过阶段。
