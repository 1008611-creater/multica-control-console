# 架构说明

## 1. 分层

```text
┌──────────────────────────────────────────┐
│  任务入口层                               │
│  议题 / 任务 / 自动化派发                 │
└───────────────────┬──────────────────────┘
                    │ 任务输入、状态和产物
┌───────────────────▼──────────────────────┐
│  规范层                                   │
│  AGENTS / CONSTRAINTS / product-spec /    │
│  acceptance / ADR                         │
└───────────────────┬──────────────────────┘
                    │ 验证与索引
┌───────────────────▼──────────────────────┐
│  资产层                                   │
│  脚本 / 模板 / 索引 / 数据                │
└───────────────────┬──────────────────────┘
                    │ 只读引用 / 人工交付
┌───────────────────▼──────────────────────┐
│  外部执行现场                             │
│  运行环境 / 原始目录 / 平台               │
└──────────────────────────────────────────┘
```

## 2. 依赖方向

```text
任务模板 -> 规范与约束 -> 资产索引 -> 外部执行现场
```

反向依赖禁止：资产不得修改根级约束；外部系统的凭据不得写回仓库；外部日志不得成为产品规格的唯一事实来源。

## 3. 外部边界

本仓库只做索引、规范、验证和结果沉淀。外部系统负责实际执行，跨边界动作必须有明确授权和可回溯证据。

## 4. 失败与回滚

- 验证失败：保留失败证据，修复后重新运行验证。
- 执行失败：不覆盖上一次可用产物，记录失败原因和重试条件。
- 状态误更新：以唯一状态真源为准，提交一条带日期的修复记录。
- 对外交付失败：状态保持等待确认，不得写成已完成。
