# 03 · 运维手册

日常只需要记住一句：**代理在线、登录态有效、同一时刻只跑一个入口。**

> 2026-09-12 起，桥支持**开机自启 + 掉线自愈**：装一次之后，机器重启服务自己起来，掉线 5 分钟内自动恢复。
> 装法见 §二·五，最省事是**双击 `1_安装开机自启.cmd`**（还没装的话，这一步现在就该做）。
> 装好之后你唯一还需要手动保证的，是**代理（127.0.0.1:7897）开着**——脚本没法替你开代理。

---

## 一、日常检查（30 秒）

```powershell
# 1. 代理在不在
Test-NetConnection 127.0.0.1 -Port 7897 -InformationLevel Quiet

# 2. 服务在不在、依赖齐不齐
Invoke-RestMethod http://127.0.0.1:8765/health
```

`/health` 里这几项必须全是 `true`：

| 字段 | 为 false 时的含义 |
|---|---|
| `runnerExists` | `scripts\mj_run.js` 不在 |
| `adapterExists` | `scripts\mxai_adapter.js` 不在，或 `MXAI_ADAPTER_PATH` 指错 |
| `profileExists` | `MXAI_PROFILE` 没设或指错，登录态找不到 |
| `nodeModulesExists` | playwright 所在目录不对，`MXAI_NODE_MODULES` 要改 |
| `ok` | 上面任一项出问题就为 false |

**另外两个字段必须核对（2026-09-12 新增，最容易漏）：**

| 字段 | 期望值 | 含义 |
|---|---|---|
| `bridge` | `2026-09-12.9` | 桥的版本号。**看不到这个字段 = 跑的是旧版进程，必须重启** |
| `timeoutMs` | `1200000` | 单次任务超时（20 分钟）。旧版 300000 会在排队约 11 分钟时掐断；900000 也会被最慢一次 913 秒擦边掐断 |

> 一句话：**`/health` 里没有 `bridge` 字段，就先重启桥，别急着出图。**

### 自启与看护装好了吗（一条命令）

```powershell
$body = @{ mode = "autostart" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/v1/maintenance -Body $body -ContentType "application/json"
```

`installed: true` 就说明两个计划任务都在。为 false 时按 §二·五 装一次（只装一次，长期有效）。

## 二·五、开机自启与看护（装一次，长期有效）

**为什么需要**：桥是「稳定出图」的唯一入口。手动开的窗口一关、机器一重启，链路就断了，
而且断得很安静 —— 任务会一直卡在排队，等到发现已经白等十几分钟。

**装一次**：

最省事的办法是**双击** `1_安装开机自启.cmd`，会弹一个「是否允许更改」的窗口，点【是】就行。

或者在 PowerShell 里跑（可能需要管理员身份）：

```powershell
powershell -ExecutionPolicy Bypass -File E:\codex\multica\mj-automation\scripts\install_autostart.ps1
```

它会注册两个计划任务：

| 任务 | 触发 | 作用 |
|---|---|---|
| `MJ-Bridge-Autostart` | 登录后 | 自动把桥拉起来（隐藏窗口，日志落 `run\logs\bridge.log`） |
| `MJ-Bridge-Watchdog` | 每 5 分钟 | 体检一次：端口没人听就拉起；进程卡死就走安全重启 |

**看状态**：双击 `2_查看运行状态.cmd`，或在 PowerShell 里跑：

```powershell
powershell -ExecutionPolicy Bypass -File E:\codex\multica\mj-automation\scripts\install_autostart.ps1 -Status
```

**卸载**：把 `-Status` 换成 `-Uninstall`。

看护的判定逻辑与最小间隔（两次动作至少间隔 120 秒，避免反复重启拖垮机器）：

| 情况 | 看护动作 |
|---|---|
| `/health` 正常 | 安静退出，只在状态从 down 恢复时记一行 `RECOVERED` |
| 8765 没人监听 | 后台拉起桥（`start_mj_bridge.ps1 -Yes -NoDuplicate`） |
| 8765 有人监听但健康检查不通 | 走桥自带的两步式安全重启（金丝雀先验证再切） |
| 距上次动手不足 120 秒 | 跳过，只记一行 `SKIP` |

看护日志：`run\logs\watchdog.log`（超过 2MB 自动滚动为 `.log.1`）；状态：`run\logs\watchdog-state.json`。

> **代理仍需你自己开。** 看护只能保证「服务在跑」；代理没开时服务是活的，但一出图就会全批卡住。

## 三·五、出图用两段式，别在 HTTP 里干等（2026-09-12 新增）

MJ 本机排队实测 **11–15 分钟**。同步等一次出图，既容易超时又容易丢单。
**标准姿势：提交后拿作业号，过几分钟回来查。**

```powershell
# 第一步：提交（付费，约 2 秒就返回作业号）
$body = @{ prompt = "……完整中文提示词……"; aspect = "9:16"; label = "M07_南天门" } | ConvertTo-Json
$job  = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/v1/jobs -Body $body -ContentType "application/json"
$job.jobId

# 第二步：过几分钟回来查（免费，随便查多少次）
$st = Invoke-RestMethod "http://127.0.0.1:8765/v1/jobs/$($job.jobId)"
$st.status   # running / done / stale
$st.images

# 看最近所有作业
Invoke-RestMethod "http://127.0.0.1:8765/v1/jobs?tail=10" | % items | Select jobId, status, ok
```

**重复提交不会重复扣费**：作业号带提示词指纹，同一条提示词已有作业在跑时直接复用，返回 `deduped: true`。
不确定上次成没成，就放心再提交一次。

**`stale` 怎么办**：日志超过约 23 分钟没动，说明进程已死。
**先别重跑**（会再扣一次）。先去站内看有没有出图，有就用 `dl_by_serial.js` 补下：

```powershell
cd E:\codex\multica\mj-automation\scripts
node dl_by_serial.js 2098561507729084416 M07_南天门
```

## 三·六、只读维护接口（免费，绝不出图）（2026-09-12 新增）

`POST /v1/maintenance` 是**免费维护通道**，白名单**八个**模式：既做只读自检，也做免费补下载（把已出好、但没取回的图重新取回）。任何模式都**不会重新生成、不会扣积分**。

```powershell
# 语法体检：python / node / powershell 三类脚本一次查完
$body = @{ mode = "lint" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/v1/maintenance -Body $body -ContentType "application/json"

# 运行环境（node 版本、超时、工作目录）
@{ mode = "env" } | ConvertTo-Json | Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/v1/maintenance -Body { $_ } -ContentType "application/json"

# 端口占用（谁在听 8765）
@{ mode = "netstat" } | ConvertTo-Json | Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/v1/maintenance -Body { $_ } -ContentType "application/json"

# 尺寸档位（只点档位、不出图、不扣积分；付费出图前建议先跑）
@{ mode = "aspect-check:9:16" } | ConvertTo-Json | Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/v1/maintenance -Body { $_ } -ContentType "application/json"
# 期望：applied = 9:16，且 chipsAfter 里 9:16 那一项带 selected-item

# 免费补下载：任务已扣费但没取回图时，用它把成品取回来（不重跑、不再扣积分）
# serial 写站点任务号即可（带不带 serial- 前缀都行）
@{ mode = "dl-serial"; serial = "2098957394129195008"; prefix = "M05_tianbing" } | ConvertTo-Json | Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/v1/maintenance -Body { $_ } -ContentType "application/json"

# 老写法仍兼容：mode = "dl-serial:<任务号>:<输出基名>"

# 改完脚本让桥自己换新版（不必手动双击）
@{ mode = "restart-bridge" } | ConvertTo-Json | Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/v1/maintenance -Body { $_ } -ContentType "application/json"
```

> 免费补下载小抄：站点对同一条任务号的「下载」按钮是一次性的，**同一条 serial 只值得下载一次**。
> 桥会先查本地归档与输出目录，命中就直接复用，连浏览器都不启动。
> 人工兜底也可直接双击 `5_补下载.cmd`，粘贴任务号即可。

| 模式 | 作用 | 关键返回字段 |
|---|---|---|
| `lint` | 只解析不执行，检查 **9 个**核心脚本的语法 | `lint.ok`（必须 true）、`results[]` |
| `lint-prompt` | 扫提示词风险词（**付费出图前的必做项**） | `scanned`、`dirty`（必须 0）、`files[]`、`referenceWords[]`（仅提示） |
| `env` | 看运行时环境 | `nodeVersion`、`envTimeout`（应为 1200000）、`cwd` |
| `netstat` | 看 8765 端口 | `pids[]` |
| `autostart` | 看开机自启/看护有没有装（2026-09-12 新增） | `installed`、`tasks[]`、`watchdogLogTail[]` |
| `aspect-check:<尺寸>` | **只点尺寸档位**，验证请求尺寸真被选中（付费出图前建议先跑） | `applied`、`chipsAfter[]`（目标档位应带 `selected-item`） |
| `dl-serial` | **免费补下载**：按任务号把已出好的图取回（先查本地缓存，命中直接复用） | `file`、`w`/`h`、`sha256`、`cached` |
| `restart-bridge` | 让桥自己换到新版本（金丝雀先验证再切） | `status=restart_scheduled`、`run\bridge-restart.log` |

`lint` 默认检查这 **9 个**文件：`server.py`、`mj_run.js`、`mxai_adapter.js`、`dl_by_serial.js`、`prompt_guard.js`、`start_mj_bridge.ps1`、`watchdog_mj_bridge.ps1`、`install_autostart.ps1`、`preflight_check.ps1`。
也可只查一个：`{ "mode": "lint", "file": "scripts/mj_run.js" }`。

**铁律一：改完任何脚本，先跑 `lint`，全绿再重启。**

**铁律二：任何一次付费出图之前，先跑 `lint-prompt`，`dirty` 必须为 0。**

**铁律三：尺寸不确定时，先跑 `aspect-check:<尺寸>` 确认档位真被选中。** 只点档位、不出图、不扣积分。历史上出现过「请求 9:16、实际点成 1:2」，图出来才发现，积分已经扣掉。

v8.2 解析器会把正文里的全大写缩写（`UHD` / `HDR` / `VFX`）与带连字符合成词（`close-up` / `game UI`）
误判成未知参数 → **整单失败**。积分会退回，但白等十几分钟排队。所以提交前先扫：

```powershell
# 扫提示词目录（免费、只读、不出图）
$body = @{ mode = "lint-prompt"; file = "E:\codex\multica\projects\天宫漫剧\prompts" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/v1/maintenance -Body $body -ContentType "application/json"
# 期望：dirty = 0。不为 0 就先按 files[].words 改提示词，改完再扫。
```

扫描器只认 Markdown 里的 `text` 代码块，且只保留**含中文**的块，说明表格与步骤清单不会误报；资产卡里的纯英文参考备份段归入 `referenceWords` 只作提示。**它只报告，绝不改你的文件**。

**整篇说明档案怎么写才不算脏**：像 `assets\12_S7_四类风格锚_v3_敦煌天宫3D仿真人.md` 这种「通篇都是风格说明、并不直接提交」的档案，
在文件里写一行 `> <!-- prompt-guard: reference-only -->`（也可写 `提示词闸门：仅参考` 或 `本文件不进入提交路径`），
闸门就会把整篇归入参考提示、不再计入 `dirty`。**真正提交的块仍然必须单独过闸门。**
全库基线：`scanned: 72, dirty: 0`。

**重启（改完代码、`lint` 全绿之后才做）**：走两步式安全重启（金丝雀先起 8766 验证 → 杀旧桥 → 起新桥 → 回收金丝雀）：

```powershell
$body = @{ prompt = "restart"; mode = "restart-bridge" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/v1/images/generations -Body $body -ContentType "application/json"
# 返回 HTTP 502 是既有行为（维护类走 detail 通道），不是失败；过程写在 run\bridge-restart.log
```

### 现象：任务全部卡住不动 / 页面一直转圈

**第一嫌疑：代理没开。** 历史上多次因为这一条导致整批任务失败。

```powershell

```

代理开着还卡 → 手工在浏览器里打开 `https://www.mxai.cn` 看能不能进。

### 现象：机器重启后 `/health` 连不上（2026-09-12 新增）

先看自启装没装：

```powershell
$body = @{ mode = "autostart" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/v1/maintenance -Body $body -ContentType "application/json"
```

连 `/health` 都不通时，直接跑一次安装脚本的 `-Status`（见 §二·五），看两个任务的 `lastResult`。
计划任务没注册 → 重跑安装脚本；注册了但 `lastResult` 非 0 → 看 `run\logs\watchdog.log` 与 `run\logs\bridge.log`。

**注意**：看护每 5 分钟才动一次手，掉线后最长需要 5 分钟恢复。急用就直接跑 `start_mj_bridge.ps1`。

### 现象：HTTP 401 / `need_login`

登录态失效。

**处理**：本人手动在弹出的浏览器窗口登录一次。登录态存在 `.browser-profile\`，登录一次能用很久。
**红线：不代登录、不保存密码。**

确认登录态（注意必须先 cd 到 scripts 目录，因为这里是相对路径）：

```powershell
cd E:\codex\multica\mj-automation\scripts
node -e "const A=require('./mxai_adapter.js');(async()=>{const a=new A({});await a.launch();await a.navigate();console.log('isLoggedIn=',await a.isLoggedIn());await a.close();})()"
```

### 现象：`Target page, context or browser has been closed` / profile 报错

**原因**：同一时刻有两个程序在用同一个 `userDataDir`。Playwright 的 profile 不能并发打开。

**处理**：

1. 确认没有第二个 `node` / `python` 进程，
2. 确认没有残留的 Edge 进程占着那个 profile，
3. Multica 批次应通过 `/v1/jobs` 保持三个作业槽位；同一 profile 的浏览器锁仍可能让作业排队，不能把排队作业取消或退回单并发。单请求 `n>1` 仅用于不需要槽位管理的场景。

```powershell
Get-Process node, python, msedge -ErrorAction SilentlyContinue | Select-Object Id, ProcessName, StartTime
```

清理残留锁文件（仅在确认没有进程占用时）：

```powershell
Remove-Item "E:\codex\niannianai\zhuanhuiyuangong\ai-rpa-console\.browser-profile\Default\LOCK" -ErrorAction SilentlyContinue
```

### 现象：`status: "download_failed"`（502）

生成其实完成了，但没拿到通过校验的高清图。

**不要立刻重跑**——重跑会再扣 6 积分，而图可能已经在站内了。

处理顺序：

1. 看返回里的 `recordId`（形如 `serial-2094365922813808640`），这是站内任务号；
2. 用补下载脚本按任务号重取：

```powershell
cd E:\codex\multica\mj-automation\scripts
node dl_by_serial.js 2094365922813808640 M07_南天门
```

3. 补下载也失败 → 打开浏览器窗口人工看一眼，确认到底出没出图。

### 现象：`status: "receipt_pending"` / `retry_allowed: false`

已经点过「立即生成」，但没拿到确定回执。**这是防重复扣费的保护，禁止自动重试。**
**2026-09-14 起：`receipt_pending` 不再参与自动补下载**（看护只挑 `queued` / `download_failed`）。

处理：人工去站内看这次任务出没出图，再用 `dl_by_serial.js` 补下载。

### 怎么验证「这一轮会不会去补下载」（零成本演练）

改完看护脚本的筛选规则后，别直接等计划任务跑 —— 那会真开一次可见浏览器。先演练：

```powershell
$b = @{ mode = 'recover-dryrun' } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/v1/maintenance -Body $b -ContentType 'application/json'
```

返回里的 `wouldPick` 就是「这一轮会挑中谁」：

- `wouldPick` 为空 → 没有该补的，看护不会开浏览器。**这是最常见的正常状态。**
- 有 `serial-…` → 那条会被补下载（免费，不扣积分）。

演练**不拉浏览器、不调补下载、不写台账**，可以随时跑。

### 现象：`status: "page_reported_failed"`（平台已判失败）

页面自己报「生成失败」，压根没出图。这是**终态**，`retry_allowed: false`，看护不会挑它，也不会自动补下载。

处理：确认后按批次授权重出。**重出会重新扣积分**（约 6 积分/张），所以必须人工点头，不做静默重试。

### 现象：`OK_HD` 通过但图片明显是缩略图

检查阈值是不是被调低了：

```powershell
$env:MJ_MIN_BYTES; $env:MJ_MIN_DIM
```

参考量级：合格高清原图 **5.6–9.3MB / 1792×2688**；四宫格整图 **1856×2464**。
低于 200KB 的一律不算。缩略图实测约 18–41KB / 330×438~495，会被拦下。

### 现象：整单失败，积分退回了

多半撞上 **v8.2 解析器 bug** —— 正文里的连字符合成词或全大写缩写被误判成未知参数。

实测触发：`close-up` / `game UI` / `plastic CGI`。

### 现象：`.ps1` 脚本报「缺少 `}`」或「字符串未终止」，但括号明明是对的（2026-09-12 新增）

**根因不是括号，是编码。** PowerShell 5.1 读**无 BOM 的 UTF-8** 时会按本地代码页（GBK）解码，
中文注释变乱码，解析器于是误报「缺少 `}`」「字符串未终止」，报错行**永远落在含中文的那几行**。

**判据**：报错行全是中文行 → 八成是 BOM 问题，不是语法问题。

**修法**：把 `.ps1` 存成 **UTF-8 with BOM**（文件开头补 `EF BB BF`），CRLF 保持不变。
`lint` 模式内置了这道守卫：`.ps1` 没 BOM 直接判 `missing_bom` 失败。

```powershell
# 检查某个 ps1 有没有 BOM（前三字节）
$b = [System.IO.File]::ReadAllBytes("E:\codex\multica\mj-automation\start_mj_bridge.ps1")[0..2]
($b | % { $_.ToString("X2") }) -join " "   # 期望 EF BB BF
```
