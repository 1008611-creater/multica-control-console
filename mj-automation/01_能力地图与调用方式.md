# 01 · 能力地图与调用方式

本文件回答一件事：**想拿到一张 MJ 图，有哪几个入口，怎么调。**
三条路都通向同一个浏览器自动化内核，产物、校验、记账完全一致。

```
                    ┌──────────────────────────────┐
   FastAPI (HTTP) ──┤                              │
   MCP (stdio)   ───┤  mxai_adapter.js             │── Edge ── mxai.cn
   CLI (直接跑)  ───┤  （Playwright 页面自动化）    │
                    └──────────────┬───────────────┘
                                   │
                        内容校验 verify_result.js
                                   │
                    ┌──────────────┴──────────────┐
                 高清原图落盘                  回执记账
                MJ_OUTPUT_DIR            receipts/mxai-tasks.jsonl
```

## 零、先决条件（每次开机都要确认）

1. **代理在线**：`127.0.0.1:7897`。代理不在线，MXAI 页面会一直卡在加载，任务全失败。
2. **登录态有效**：复用 `.browser-profile\`，实测 `isLoggedIn = true`。失效时服务返回 401，需本人手动登录一次（红线：不代登录）。
3. **没有别的程序占用 profile**：Playwright 的 `userDataDir` 不能由多个浏览器实例同时打开。批次层仍保持三个桥作业占槽；未抢到 profile 锁的作业等待，不得因此退回单并发。
4. **积分充足**：每次生成约 6 积分。

适合被别的程序调用：Multica 任务、画布渠道、脚本批量出图。

接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/health` | 自检：runner / adapter / profile / node_modules / 输出目录是否就位 |
| GET | `/v1/models` | 返回 `midjourney`，供画布「拉取模型列表」 |
| POST | `/v1/images/generations` | 出图（OpenAI 兼容格式） |
| GET | `/v1/receipts?tail=50` | 只读回执台账，用于对账 |
| POST | `/v1/jobs` | **推荐**：提交出图，立刻返回作业号（付费，约 6 积分） |
| GET | `/v1/jobs?tail=20` | 列出最近作业，只读免费 |
| GET | `/v1/jobs/{作业号}` | 查单个作业结果，只读免费 |

出图请求：

```json
POST /v1/images/generations
{
  "prompt": "一位身披金甲的东方武将站在天门之前，逆光，写实电影感，自然语言成句，参数放末尾 --v 8.2 --ar 9:16 --raw --stylize 250 --chaos 5 --no text, watermark, logo",
  "n": 1,
  "aspect": "9:16"

```

请求字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `prompt` | 是 | 完整提示词，**参数写在正文末尾** |
| `n` | 否 | 出几张，默认 1，上限 15。单请求的 `n>1` 仍由服务内部串行；批次并发请使用 `/v1/jobs` 的三个作业槽位 |
| `aspect` | 否 | `9:16` / `16:9` / `1:1` / `3:4` 等，默认 `9:16` |
| `size` | 否 | 像素尺寸如 `1024x1536`，会自动换算成最接近的档位。有 `aspect` 时以 `aspect` 为准 |
| `mode` | 否 | `normal` / `fast`，默认 `normal` |
| `model` | 否 | 仅回显，不影响行为 |

成功响应：

```json
{
  "created": 1757500000,
  "aspect": "9:16",
  "status": "ok",
  "recordIds": ["serial-2094365922813808640"],
  "data": [{ "b64_json": "data:image/png;base64,....", "url": null }],
  "_meta": { "statuses": ["ok"], "requestedAspect": "9:16", "mode": "normal" }

```

失败响应（HTTP 状态码 + 结构化 detail）：

| 状态码 | status | 含义 | 你要做什么 |
|---|---|---|---|
| 400 | `bad_request` | 提示词为空 | 改请求 |
| 401 | `need_login` | 登录态失效 | 手动登录一次 |
| 502 | `download_failed` | 生成完成但没拿到合格高清图 | **先人工去站内看**，别急着重跑 |
| 502 | `no_output` / `unparsable` | 桥接没返回或返回不可解析 | 看服务端 stderr |
| 504 | `timeout` | 超时 | 先人工确认站内是否已出图 |

```json
HTTP 502
{ "detail": { "status": "download_failed", "message": "...（被校验拦下的文件：3 个）", "aspect": "9:16" } }
```


### 入口 A+ · 两段式出图（推荐给 Multica，2026-09-12 新增）

**为什么要有它：** MJ 本机排队实测 **11–15 分钟**（最慢一次 913 秒）。
如果用 `/v1/images/generations` 同步等，调用方一断开，图就没人收；把超时调大又会长时间占着连接。
两段式把「等」这件事从 HTTP 里挪出去：**提交立刻返回，过一会儿回来查。**

```text
第一步（付费，约 2 秒返回）        第二步（免费，随时查）
POST /v1/jobs                    GET /v1/jobs/{作业号}
  → 202 { jobId, status: running }   → done    拿到图
                                     → running 还在跑，等几分钟再查
                                     → stale   进程已死，人工去站内看
```

提交：

```json
POST /v1/jobs
{ "prompt": "……完整中文提示词……", "aspect": "9:16", "label": "M07_南天门" }
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `prompt` | 是 | 完整提示词 |
| `aspect` | 否 | 默认 `9:16`，也可用 `size` 换算 |
| `label` | 否 | 人看得懂的作业名前缀，会截到 56 字 |
| `force` | 否 | 默认 `false`。**同一提示词已有作业在跑时，默认直接复用、不重复扣费**；只有明确要再出一张才置 `true` |
| `version` | 否 | 默认 `v8.2` |

立刻返回（HTTP 202）：

```json
{
  "jobId": "M07_南天门_a1b2c3d4e5",
  "status": "running",
  "deduped": false,
  "pollWith": "/v1/jobs/M07_南天门_a1b2c3d4e5",
  "message": "已开始出图。MJ 本机排队实测 11~15 分钟，请稍后用上面的地址回来查，不要重复提交。"
}
```

查到结果（免费）：

```json
{ "jobId": "M07_南天门_a1b2c3d4e5", "status": "done", "ok": true,
  "images": ["E:\\codex\\multica\\mj-automation\\output\\M07_南天门_....png"],
  "aspect": { "ok": true, "requested": "9:16", "applied": "9:16" },
  "recordId": "serial-2098..." }
```

`status` 只有四种，按它决定下一步：

| status | 含义 | 你要做什么 |
|---|---|---|
| `running` | 还在跑 | 等 2–3 分钟再查，**不要重新提交** |
| `done` | 出好了 | 取 `images` 里的路径 |
| `stale` | 日志超过约 23 分钟没更新，进程基本已死 | 人工去站内看有没有图，用 `dl-serial` 补下 |
| `unknown`（HTTP 404） | 没有这个作业号 | 核对作业号 |

**防重复扣费（写死在服务里）：** 作业号尾部带提示词的指纹（sha256 前 10 位）。
提交前先扫 `run\jobs\`，同指纹已有作业在跑就直接复用，返回 `deduped: true`，**一分积分不扣**。
所以「不确定上次提交成没成」时，**放心再提交一次**，不会重复付费。

作业结果落盘在 `run\jobs\<作业号>.json`，进程重启也不丢单。

### 入口 A++ · 免费自检两条（2026-09-12 新增）

这两条**不出图、不扣积分**，是每次开工前和改完代码后的标准动作。

**① 只读维护：`POST /v1/maintenance`**

白名单**六个**模式：`lint`（三类脚本语法体检，只解析不执行，覆盖 **9 个**文件）、`lint-prompt`（提示词风险词扫描）、`env`（运行时环境）、`netstat`（端口占用）、`autostart`（查开机自启与看护的注册状态、看护日志尾部）、`aspect-check`（**只点尺寸档位**，验证请求的尺寸真被选中，不出图、不扣积分）。
可加 `file` 只查一个：`{ "mode": "lint", "file": "scripts/mj_run.js" }`。

**`aspect-check`：付费出图前的尺寸闸门（免费）**

写法是把尺寸内联在模式后面：`{ "mode": "aspect-check:9:16" }`（可选值 `1:1` / `1:2` / `16:9` / `9:16` / `4:3` / `3:4` / `3:2` / `2:3`）。返回 `applied` 与 `chipsAfter[]`，目标档位在 `chipsAfter` 里应带 `selected-item`。

只有 `aspect-check` 允许携带内联参数，其它模式带 `:` 会被 400 拒绝（`inline_not_allowed`），非法尺寸值会被 400 拒绝（`bad_aspect`）——内联串不会被透传给子进程。

`lint` 默认体检 **8 个**核心文件：`server.py`、`mj_run.js`、`mxai_adapter.js`、`dl_by_serial.js`、`prompt_guard.js`、`start_mj_bridge.ps1`、`watchdog_mj_bridge.ps1`、`install_autostart.ps1`。

**`lint-prompt`：提交前的提示词闸门（免费）**

为什么需要：v8.2 解析器会把正文里的**全大写拉丁缩写**与**带连字符合成词**误判成未知参数 → **整单失败**。
积分虽退回，但白等十几分钟。所以**任何一次付费出图之前，先扫一遍**。

```powershell
# 扫整个提示词目录
$body = @{ mode = "lint-prompt"; file = "E:\codex\multica\projects\天宫漫剧\prompts" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/v1/maintenance -Body $body -ContentType "application/json"
```

| 返回字段 | 含义 |
|---|---|
| `scanned` | 扫了几个 Markdown 文件 |
| `dirty` | 有几个文件含风险词。**必须是 0 才允许提交** |
| `referenceOnly` | 该文件是否被标成「仅参考」（写了 `prompt-guard: reference-only`）；是则整篇只提示、不计入 `dirty` |
| `files[].words` | 具体命中的风险词，据此替换 |
| `referenceWords` | 纯英文「参考备份块」里出现的风险词，**只提示、不计入 `dirty`** |

**只扫真会提交的那段**：只认 Markdown 里的 `text` 代码块，跳过表格/批次总览/步骤清单，并只保留**含中文**的块，
不会把文档里的解释文字误判成风险词。资产卡里的 `English Reference Version` 纯英文备份段单独归入 `referenceWords`。
**本接口只报告、绝不改文件。**

**实测基线（2026-09-12）**：全库 `scanned: 72`、`dirty: 0`（参考词只提示、不影响放行）。

### 入口 A+++ · 出图前自检（双击就行，2026-09-12 新增）

双击 `4_出图前自检.cmd`，等于把下面四道闸门一次跑完，最后直接给结论：

1. 桥在不在 + 代理地址（代理没开是最常见的整批卡死原因）
2. `lint` 脚本语法（**9 个**文件全绿）
3. `lint-prompt` 提示词风险词（只提示、不阻断）
4. `aspect-check:9:16` 尺寸档位真被选中

结尾会打印「**可以出图（每一批仍需你当次授权）**」或「**先别出图**」。它只读、不出图、不扣积分。

**② 页面探针：`POST /v1/images/generations { "mode": "probe" }`**

只启动浏览器读页面 DOM，验证四件事：**浏览器能不能起、登录态还在不在、代理通不通、页面有没有改版**。
返回是 HTTP 502，但**这是既有行为不是失败**——数据在 `detail.message` 的 `PROBE {...}` 里。

| 探针字段 | 含义 |
|---|---|
| `cardCount` | 页面上能看到几张历史卡片（0 = 没登录或没加载出来） |
| `newestId` | 最新一张的站内 serial，可拿去 `dl_by_serial.js` 补下 |
| `newestHasDownloadSpan` | 最新那张有没有「下载」按钮（false = 图还没好或是垃圾） |
| `credits` | 积分余额与失败提示文本 |
| `arChips` | 页面实际的尺寸档位（当前八档，`selected-item` 是当前选中项） |
| `pageHasFailedText` | 页面上有没有失败提示 |

**实测基线（2026-09-12 探针）**：18 秒返回，`cardCount: 10`，积分 3193，尺寸八档，`9:16` 已选中，最新图带下载按钮。

## 二、返回里必须看的三个字段

| 字段 | 为什么重要 |
|---|---|
| `status` | `ok` 才算真拿到图。`download_failed` / `receipt_pending` / `page_reported_failed` 不做静默自动重跑；`page_reported_failed` 是本次作业终态，但在本批授权内可人工确认后重新提交，且会产生新作业/新扣费 |
| `aspect` | 页面**实际选中**的档位，取自回读结果。2026-09-12 探针实测页面为**八档**（1:1 / 1:2 / 16:9 / 9:16 / 4:3 / 3:4 / 3:2 / 2:3），`9:16` 可**直选**。回读不一致会抛 `ASPECT_NOT_APPLIED`（在点生成前，不扣费） |
| `files[].sha256` | 同提示词同参数可复现。实测两条不同名字的产物哈希相同，说明管道稳定 |

## 三、中文版 MXAI 的硬事实（写死了，别猜）

| 权威参数 | 界面怎么操作 |
|---|---|
| `--ar 9:16` | 直选 **9:16**（页面原生档位，无需映射） |
| `--ar 16:9` | 直选 **16:9**（页面原生档位） |

  > 旧文档「只有 4 档、9:16 要映射成 1:2」的结论**已作废**。
- **比例只有一个权威来源**：界面档位。正文里的 `--ar` / `--aspect` 会在选档前被自动剥离（`stripAspectParams`），避免两个来源互相覆盖。

- 参考图用**波浪号**写在正文：`~sref` 风格 / `~oref` 角色身份。

- **中文执行版不受这个 bug 影响 → 优先用中文提示词。**

## 四、提示词三档预设（天宫漫剧用）

