## 四、断点与修复状态（按修复优先级）

### 断点 1（最关键）· 下载失败时静默降级成缩略图，且对外仍报成功

先说清楚一件事，避免误判：**「下载」按钮拿回来的是整张四宫格，是一个文件，不是四张。**
（`mxai-ui-guide.md` 与 `SKILL.md` 都记载为「整张 4 宫格，约 1856×2464」。）

真正的问题在两层：

**第一层 · 主路径一旦不出结果，就跌到抓缩略图。**

`mxai_adapter.js:831–839`：`downloadLatestViaButton()` 捕获到 download 事件后保存文件并立即 `return`。

`mxai_adapter.js:1143–1151`：`generate()` 里判断 `if (!images.length)` 才走兜底；一旦主路径失败，直接跌落到 `downloadLatestImages()`，而后者抓的是**缩略图 URL**。

**第二层 · 跌下来之后没有任何内容校验，垃圾也算成功。**

`downloadLatestViaButton` 与 `downloadLatestImages` 都只看「文件有没有写成功」，不看拿到的是什么：

- 140KB 的 loading GIF → 当成图片存了；
- 1KB 的错误响应体 → 当成图片存了；
- 20–40KB 的缩略图 → 当成图片存了。

然后 `generate()` 返回 `success: true`。

**这两层叠加，就是「有时 7.7MB、有时 32KB」的全部原因。** 真实日志佐证：

```
[MXAI] 警告: serial serial-2094365922813808640 长时间未出「下载」按钮，交由下载阶段重试
[MXAI] 待下载图片: 4 张
[MXAI] 已下载: niannian_cine_1.gif (140077 bytes)     ← loading 占位图
[MXAI] 已下载: niannian_cine_2.png (41886 bytes)      ← 缩略图
[MXAI] 按钮下载无结果，已回退 URL 抓取
GEN success=true images=4                              ← 报告"成功"，实际全是垃圾
```

**注意最后一行**：流程对外报 `success=true`，但拿到的全是废图。这是最危险的一点——**假成功**。

### 断点 2 · 没有内容校验，垃圾被当成产物

下载完成后只检查「文件是否存在」，不检查尺寸、字节数、是否 PNG/JPEG 魔数。GIF 占位图（140KB）和错误页（1KB）都能通过。

讽刺的是，`dl_by_serial.js` 里**已经写好**了 `dimOf()` 尺寸解析 + `minW/minH` 校验 + `VERDICT=TOO_SMALL` 判定 —— **这套校验没有合进主流程**。

### 断点 3 · 比例的「两个来源」互相打架（已修复）

原判「中文版只有 1:1 / 1:2 / 3:4 / 3:2 四档、需要做映射表」**经页面探针实测作废**：

- 尺寸按钮实为**八档**：`1:1 / 1:2 / 16:9 / 9:16 / 4:3 / 3:4 / 3:2 / 2:3`（按页面顺序）。
- 所以 `--ar 9:16` 可以**直选**，不需要任何映射。

真正的问题是**比例有两个来源**：提示词正文里的 `--ar` 会被页面解析器当成参数，与界面档位选择**互相覆盖**，于是出现「我点了 9:16，出来却是 1:2」的错位。

修复（`mxai_adapter.js`，缺陷 J）：

- **页面档位是唯一权威**：点档位前先 `stripAspectParams()` 把正文里的 `--ar` / `--aspect` 剥离，杜绝双来源打架；
- 点完档位后**回读选中态**，确认真的生效；
- 回读不一致时抛 `ASPECT_NOT_APPLIED`，**在点「生成」之前抛出 → 不扣费**；
- 新增 `allowAspectDegrade = false`（默认关闭）：宁可失败，也不悄悄降级画幅；
- 回执记录三个字段（请求比例 / 实际比例 / 是否降级），便于事后追责。

### 附带发现 · 一个「看起来像语法错误、其实是编码」的陷阱（2026-09-12 结案）

- 现象：`start_mj_bridge.ps1` 报「缺少 `}`」「字符串未终止」，且报错行**全是含中文的行**。
- 误判：先以为是括号配平问题（确实也存在一处多余 `}`，已一并修掉）。
- 真因：该文件是**无 BOM 的 UTF-8**。PowerShell 5.1 按本地代码页（GBK）解码 → 中文变乱码 → 解析器误报。
- 证据：同一文件加 BOM 后立刻 `syntax-ok`（对照实验已做）。
- 修法：补 `\uFEFF`，CRLF 保持不变。`lint` 模式内置 BOM 守卫，`.ps1` 缺 BOM 直接判 `missing_bom` 失败。
- 结论：**本项目所有 `.ps1` 必须存成 UTF-8 with BOM。** 这条已写进运维手册。

  ② 带连字符合成词（`close-up`、`game UI` 这类）；③ 正文中段出现的参数令牌（应统一挪到末尾）。
  命中即给出中文替换建议（如 `8K`→极致锐利、`CGI`→三维渲染、`HDR`→高动态范围），**只报告、绝不改文件**。
- **修法二（新增接口）**：`POST /v1/maintenance { "mode": "lint-prompt", "file": "<目录或文件>" }`，
  批量扫 Markdown，返回 `{ scanned, dirty, files[], referenceWords[] }`。**`dirty: 0` 才算干净。**
- **只扫「真会提交的那段」**：`extractPromptBlocks()` 只认 Markdown 里的 `text` 代码块，
  且跳过表格/流程图字符块（框线、箭头、勾选框），并只保留**含中文**的块 ——
  避免把说明表格、批次总览表、步骤清单误判成风险词。
- **闸门「假绿」缺陷（本轮修复）**：旧版把「中文占比 < 40%」的块整块跳过，
  于是 `极致清晰 4K 画质，close-up 特写，HDR 光影` 这类中英混排的真提示词被漏检，`blocks=0` 却报 `ok=true`。
  现删除该比例过滤，只保留「含中文 + 非 `--` 开头 + 无制表符连线字符」三条判据；同一脏样例现已正确报 `ok=false, total=3`（`HDR` / `close-up` / `4K`）。
- **英文参考块单独提示**：资产卡里的 `English Reference Version` 备份段是纯英文，命中词多（实测 54 个），
  若并入 `dirty` 会淹没真提交路径的判断。现由 `extractReferenceBlocks()` 单独汇总为 `referenceWords`，**只提示、不判失败**。
- **存量净化复核（本轮已完成）**：`projects\天宫漫剧\prompts\资产提示词\` 下 **28 个**文件（非 15 个）逐文件复核，
  在新判据下仍为 `total = 0` —— 上一轮净化**真实有效**，此前的「干净」只是旧判据的假绿掩盖。
- **验收实测**：`lint` 全绿（**9 个**核心脚本 PASS，已含 `prompt_guard.js`、两个自启/看护脚本与 `preflight_check.ps1`）；
  `lint-prompt` 全库复扫 → **`scanned: 72, dirty: 0`** ✅（参考词只提示、不计入 `dirty`）。
- **注意**：`资产提示词\` 下 M02 / M04 / M05 / M06 / M09 / M10 / M12–M17 这些文件是**只读**（mode `100444`）。
  它们当前内容本就干净；将来若需改写，先解除只读属性再动，扫描器不会强写。

## 八、风险清单

| 风险 | 说明 | 缓解 |
|---|---|---|
| 登录态过期 | `.browser-profile\` 里的 cookie 会失效 | 提供重新登录脚本；失效时提示你手动登录一次 |
| 风控 / 验证码 | 站点可能弹真人校验 | 检测到即停止，提示你手动处理，**不绕过** |
| profile 被两个入口同时占用 | Playwright 的 userDataDir 不能并发打开 | 统一执行层内加文件锁，串行化 |
| 积分消耗 | 每次生成 6 积分，属付费动作 | 按批次授权，每批问一次；单次调用前报数 |
| 假成功 | 当前会报 success 但产物是垃圾 | 加内容校验，不合格必须报失败 |
| 站点改版 | 选择器可能失效 | 保留 `mxai_diag` 诊断工具，失效时能快速定位 |
| 提示词误判 | v8.2 解析器对连字符/大写缩写敏感 | 中文执行版优先；英文版过安全词汇表 |
