## 输入

- `scripts/verify.ps1`（Slice 12 的扫描范围与 Markdown 检查）
- 仓库文档间的跨文件引用，以及 `project_state.yaml` 中的路径声明

## 发现的缺口

1. 验证脚本不检查文档内部引用。重命名或移动文档后，指向旧路径的链接会静默失效，直到有人点击才发现。
2. 验证脚本不检查项目状态里的路径声明。`paths.control_console` 即使指向错误目录也能通过验证，项目身份与控制台位置可能悄悄脱节。

## 执行内容

1. 新增 Markdown 相对链接检查：`](./...)` 与 `](../...)` 形式的引用必须指向真实存在的文件，断链即失败。
2. 新增控制台路径一致性检查：项目状态声明的 `control_console` 必须以该项目控制台的实际相对路径结尾。
3. 更新验证通过时的输出文案，使其与真实检查项一致。

## 验证证据

| 检查项 | 方式 | 结果 |
|---|---|---|
| 全仓基线 | `npm run verify` | PASS，退出码 0 |
| 断链能拦截 | 植入指向不存在文件的相对链接 | FAIL 如期触发，提示相对链接失效；探针已删除 |
| 路径漂移能拦截 | 在仓库快照副本中把 `control_console` 改指向错误目录 | FAIL 如期触发，提示控制台路径不一致 |
| 恢复后正常 | 快照副本还原后重跑 | PASS，退出码 0 |
| 工作区状态 | `git status` | 只有本次受控改动，无临时探针残留 |

## 结论

两类隐蔽漂移现在都能在提交前被拦截：文档断链和项目路径声明错位。两项检查均通过真实探针触发失败路径，不是空跑。
